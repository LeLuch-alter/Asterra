ASTERRA — ТЕОРИЯ ПРОЕКТА
=========================
Как устроена платформа, какие инструменты и технологии используются
и по какому принципу всё работает.


1. ЧТО ЭТО ЗА ПРОЕКТ
--------------------

Asterra — платформа для научного сотрудничества, «GitHub для науки».
Студенты, исследователи и менторы могут:

  - создавать исследовательские проекты (идея, вопрос, гипотеза, методология);
  - собирать команду: находить людей, добавлять в друзья, приглашать в проект;
  - вести результаты исследования (заметки, находки, черновики разделов);
  - планировать работу по roadmap (список этапов исследования);
  - читать научные новости;
  - использовать три ИИ-функции:
      * AI Research Roadmap — из описания проекта генерируется план исследования;
      * AI Match — подбор подходящих соавторов/менторов с объяснением, почему;
      * AI Research Assistant — суммирует, объясняет, рецензирует текст,
        предлагает исследовательские вопросы и улучшения.

Это учебный демонстрационный проект. Он рассчитан на бесплатную/дешёвую
инфраструктуру и на то, чтобы его понимала и поддерживала студенческая команда.


2. ОБЩАЯ АРХИТЕКТУРА
--------------------

Проект — одно приложение на Next.js, которое одновременно является и фронтендом,
и бэкендом. Отдельного сервера (Spring, Express и т.п.) нет.

   Браузер пользователя
        |
        v
   Next.js (размещён на Vercel)
        |
        +-- React-страницы (UI)
        +-- Server Components  — читают данные из базы на сервере
        +-- Server Actions     — изменения данных (формы, кнопки)
        +-- Route Handlers     — HTTP-эндпоинты /api/* (ИИ, новости)
        |
        +-- Supabase  (PostgreSQL + Auth + Storage + Realtime)
        +-- Gemini API (или OpenAI / Grok) — ИИ, только с сервера
        +-- RSS-ленты / NewsAPI — научные новости

Главный принцип: всё «секретное» и всё, что работает с внешними API,
выполняется на сервере. В браузер попадают только публичный адрес Supabase
и публичный (publishable) ключ, защищённый политиками доступа к базе.


3. ТЕХНОЛОГИИ И ИНСТРУМЕНТЫ
---------------------------

3.1. Next.js 16 (App Router) + React 19 + TypeScript
     Фреймворк приложения. Даёт маршрутизацию по папкам (src/app/...),
     серверный рендеринг, Server Actions и API-эндпоинты в одном проекте.
     TypeScript — строгая типизация, ошибки ловятся до запуска.

3.2. Tailwind CSS 4 + shadcn/ui + Lucide
     Tailwind — стилизация утилитарными классами прямо в разметке.
     shadcn/ui — готовые доступные компоненты (кнопки, диалоги, поля),
     которые лежат в проекте как обычный код и легко меняются.
     Lucide — набор иконок.

3.3. Supabase
     Облачный PostgreSQL с готовыми сервисами:
       - Auth — регистрация/вход по email и паролю, сессии в cookie;
       - Database — таблицы проекта;
       - Row Level Security (RLS) — правила «кто что видит и меняет»
         прямо в базе (см. раздел 6);
       - Storage — хранение аватарок (bucket "avatars");
       - Realtime — подписка браузера на новые строки таблицы notifications.

3.4. ИИ-провайдер
     Gemini API (Google) по умолчанию; OpenAI и Grok (xAI) — по переключателю.
     Код провайдера изолирован в src/lib/ai/, остальное приложение
     о конкретной модели не знает.

3.5. Новости
     rss-parser читает RSS-ленты (Nature, Ars Technica, ScienceDaily),
     при наличии ключа — NewsAPI. Если всё недоступно — встроенные демо-новости.

3.6. Zod
     Библиотека проверки данных. Ей проверяются все формы и ВСЕ ответы ИИ
     перед тем, как попасть в интерфейс.

3.7. next-themes
     Светлая/тёмная тема, класс .dark на <html>, выбор сохраняется.

3.8. Git + GitHub + Vercel
     Код хранится на GitHub. Vercel при каждом push в main сам собирает
     и публикует сайт. Секреты живут в переменных окружения Vercel,
     в git они не попадают.


4. СТРУКТУРА КОДА
-----------------

src/
  app/                — страницы и маршруты (только композиция, без логики)
    page.tsx          — публичная главная: hero + лента научных новостей
    (auth)/           — вход и регистрация
    (app)/            — защищённая зона (нужен вход): dashboard, projects,
                        researchers, connections, bookmarks, search, news,
                        notifications, profile
    api/ai/*          — эндпоинты трёх ИИ-функций
    api/news          — новости в JSON
    auth/callback     — обмен кода подтверждения Supabase на сессию
  actions/            — Server Actions: все изменения данных
  components/         — переиспользуемые React-компоненты
  lib/
    supabase/         — клиенты Supabase (браузерный и серверный) + запросы
    ai/               — провайдер, промпты, схемы ответов, три функции
    news/             — загрузка новостей + запасные данные
    validation/       — zod-схемы форм
    env.ts            — единственное место чтения переменных окружения
  types/              — типы базы данных и приложения
  proxy.ts            — выполняется перед каждым запросом: обновляет сессию,
                        перенаправляет гостей на /login

supabase/
  migrations/         — SQL-файлы схемы базы (0001, 0002, 0003)
  seed.sql            — демо-данные (6 аккаунтов, проекты, результаты)

Подробная карта — в ARCHITECTURE.md.


5. МОДЕЛЬ ДАННЫХ
----------------

profiles               — профиль пользователя (1:1 с auth.users): имя, фото,
                         био, организация, роль, области науки, навыки, интересы
projects               — проект: заголовок, описание, поле, вопрос, гипотеза,
                         методология, статус, видимость (public/private)
project_members        — участники проекта и их роль (owner/researcher/
                         mentor/contributor)
research_results       — результаты/заметки проекта с автором
research_roadmap_items — этапы roadmap: заголовок, описание, позиция, статус
match_results          — кэш результатов AI Match
news_items             — кэш/запас новостей
notifications          — уведомления пользователя (тип + JSON-данные)
connections            — «дружба»: запрос → принят
project_join_requests  — заявка «хочу в проект» → владелец решает
project_invitations    — приглашение владельца другу → друг решает
bookmarks              — сохранённые проекты

Триггеры в базе: при регистрации автоматически создаётся profile;
при создании проекта владелец автоматически становится участником.


6. БЕЗОПАСНОСТЬ И ПРАВА ДОСТУПА
-------------------------------

Права проверяются в базе через Row Level Security — даже если кто-то
обойдёт интерфейс, Postgres не отдаст и не изменит чужие данные.

  - Профили видят все вошедшие; редактирует только владелец.
  - Публичные проекты видят все; приватные — только участники.
  - Редактировать проект могут участники, удалять — владелец.
  - Результаты и roadmap пишут только участники проекта.
  - В команду попадают ТОЛЬКО с согласия обеих сторон:
      * владелец приглашает — но только человека из своих connections
        (это правило зашито в RLS-политику вставки в project_invitations),
        а тот принимает или отклоняет;
      * человек подаёт заявку — владелец принимает или отклоняет.
    Принятие приглашения выполняется функцией accept_project_invitation()
    с правами определителя: она проверяет, что вызывает именно приглашённый,
    и только тогда добавляет его в project_members.
  - Аватар: каждый пишет только в свою папку <user_id>/ в bucket "avatars".
  - Уведомления: каждый видит только свои.

Ключи ИИ и секретный ключ Supabase в браузер не попадают никогда:
их читает только серверный код через src/lib/env.ts.


7. КАК ПРОХОДИТ ЗАПРОС (ПРИНЦИП РАБОТЫ)
---------------------------------------

7.1. Открытие страницы
     Браузер → proxy.ts (обновляет сессию Supabase из cookie; если страница
     защищённая и сессии нет — редирект на /login) → Server Component
     страницы запрашивает данные из Supabase → готовый HTML отправляется
     в браузер. Данные никогда не грузятся «с клиента напрямую в базу».

7.2. Изменение данных (например, создание проекта)
     Форма отправляется в Server Action (src/actions/projects.ts):
       1) проверка, что пользователь вошёл;
       2) проверка полей zod-схемой;
       3) запрос к Supabase (RLS проверяет права);
       4) revalidatePath — Next.js обновляет закэшированные страницы;
       5) редирект или результат { ok, error } обратно в форму.

7.3. ИИ-функция (например, roadmap)
     Кнопка в браузере → POST /api/ai/roadmap { projectId }
       → сервер проверяет вход и членство в проекте
       → загружает проект из базы
       → собирает промпт (src/lib/ai/prompts) с контекстом проекта
       → вызывает провайдер (Gemini) с требованием ответить JSON
       → ответ разбирается и проверяется zod-схемой
       → JSON уходит в браузер как ЧЕРНОВИК.
     Пользователь редактирует черновик и только потом сохраняет его
     через Server Action. ИИ никогда не пишет в базу сам.
     Если модель перегружена (503) или снята Google (404), провайдер
     автоматически пробует запасные модели по цепочке.

7.4. AI Match
     Сначала SQL-предфильтр: берутся профили, не состоящие в проекте,
     ранжируются по совпадению области и навыков — модели отправляется
     короткий список (до 25 человек), а не вся база. Модель возвращает
     оценку «подходит примерно на N%» и текстовое объяснение. В интерфейсе
     подчёркивается: это помощь, а не объективное измерение. Для незнакомых
     показывается «Connect», для друзей — «Invite to project».

7.5. Уведомления в реальном времени
     Server Action вставляет строку в notifications. Браузер получателя
     подписан на свои строки через Supabase Realtime (WebSocket) — приходит
     событие, показывается всплывающее сообщение, обновляются счётчики.

7.6. Новости
     Сервер раз в 30 минут загружает RSS/NewsAPI (кэш unstable_cache),
     классифицирует по ключевым словам в категории, сортирует по дате.
     Ошибка любого источника не ломает страницу — есть запасные данные.


8. ДИЗАЙН
---------

Плоские цвета без градиентов. Тёмная тема: глубокий синий + кремовый текст;
светлая: тёплая бумага + чернильный текст; один акцент — периванкль.
Шрифты: Instrument Serif (заголовки, курсивный акцент), Manrope (текст),
Geist Mono (мелкие трекинг-подписи). Анимация «орбита» на страницах входа —
чистый SVG + CSS-трансформации, отключается при prefers-reduced-motion.
Все цвета заданы токенами в src/app/globals.css.


9. ЗАПУСК И РАЗВЁРТЫВАНИЕ
-------------------------

Локально:  npm install → скопировать .env.example в .env.local и заполнить
           → npm run dev → http://localhost:3000
База:      выполнить в Supabase SQL Editor миграции 0001, 0002, 0003,
           затем seed.sql (демо-аккаунты, пароль demo1234)
Прод:      push в GitHub → Vercel собирает автоматически;
           переменные окружения задаются в настройках Vercel;
           в Supabase указывается адрес сайта и /auth/callback.

Проверки качества: npx tsc --noEmit (типы), npm run lint (ESLint),
npm run build (сборка как на Vercel).


10. ДЕМО-СЦЕНАРИЙ
-----------------

 1. Регистрация → заполнение профиля (области, навыки, фото).
 2. Создание проекта.
 3. Roadmap: генерация ИИ → правка → сохранение → отметка этапов.
 4. Researchers: найти человека → Connect → он принимает.
 5. Team → Invite друга → друг принимает уведомление → он в команде.
 6. AI Match: рекомендации соавторов/менторов с объяснением.
 7. Results: добавить результат → AI Assistant: summarize / review.
 8. Главная: научные новости по категориям.
 9. Проект находится через поиск и фильтры; его можно сохранить в закладки.


11. ЧТО СОЗНАТЕЛЬНО НЕ ДЕЛАЛОСЬ
-------------------------------

Микросервисы, свой сервер, Kubernetes, реальные интеграции с университетами
и госсистемами, платежи, совместное редактирование в реальном времени,
научное рецензирование, продакшн-рекомендательная система. Цель —
понятный, надёжный и красивый демонстрационный продукт, а не масштабная
инфраструктура.
